# InputGroup

Group related input controls with prefix and suffix elements for enhanced form fields.

## Import

```tsx
import { InputGroup } from "heroui-solid";
```

### Anatomy

```tsx
import { InputGroup, TextField, Label, Input } from "heroui-solid";

export default () => (
  <TextField>
    <Label />
    <InputGroup>
      <InputGroup.Prefix />
      <Input /> {/* Or use TextArea for multiline input */}
      <InputGroup.Suffix />
    </InputGroup>
  </TextField>
);
```

> **InputGroup** wraps an input field with optional prefix and suffix elements, creating a visually cohesive group. It's typically used within **[TextField](/docs/components/text-field)** to add icons, text, buttons, or other elements before or after the input. Like TextField, InputGroup has no `Input`/`TextArea` sub-parts — drop a standalone **[Input](/docs/components/input)** or **[TextArea](/docs/components/text-area)** inside it and it re-slots itself to fit the group.

        </InputGroup.Suffix>

### Customizing the component classes

InputGroup uses CSS classes that can be customized. Override the component classes to match your design system.

```css
@layer components {
  .input-group {
    @apply bg-field text-field-foreground shadow-field rounded-field inline-flex min-h-9 items-center overflow-hidden border text-sm outline-none;
  }

  .input-group__input {
    @apply flex-1 rounded-none border-0 bg-transparent px-3 py-2 shadow-none outline-none;
  }

  .input-group__prefix {
    @apply text-field-placeholder rounded-l-field flex h-full items-center justify-center rounded-r-none bg-transparent px-3;
  }

  .input-group__suffix {
    @apply text-field-placeholder rounded-r-field flex h-full items-center justify-center rounded-l-none bg-transparent px-3;
  }

  /* Secondary variant */
  .input-group--secondary {
    @apply shadow-none;
    background-color: var(--color-default);
  }
}
```

### CSS Classes

- `.input-group` – Root container with border, background, and flex layout. Uses `min-h-9` for flexible height and `items-center` by default, switching to `items-start` when a textarea is present.
- `.input-group__input` – Input element with transparent background and no border. Also used as the base class for textarea elements.
- `.input-group__prefix` – Prefix container with left border radius. Aligns to top when used with textarea.
- `.input-group__suffix` – Suffix container with right border radius. Aligns to top when used with textarea.
- `.input-group--primary` – Primary variant with shadow (default)
- `.input-group--secondary` – Secondary variant without shadow, suitable for use in surfaces

> **Note:** When a `TextArea` is present, the container automatically switches from `items-center` to `items-start` alignment and uses `height: auto` instead of a fixed height. Prefix and suffix elements align to the top with additional padding to match the textarea's vertical padding. The textarea uses the same `.input-group__input` base class with textarea-specific styles (minimum height and vertical resize) applied via the `[data-slot="input-group-textarea"]` attribute selector.

### Interactive States

InputGroup manages these data attributes based on its state:

- **Hover**: styled via native `:hover:not(:focus-within)` on the group — no attribute needed.
- **Focus Within**: styled via native `:has([data-slot="input-group-input"]:focus)` on the group — no attribute needed.
- **Invalid**: `[data-invalid="true"]` - Mirrored onto the group from a parent TextField with `validationState="invalid"`.
- **Disabled**: `[data-disabled="true"]` - Mirrored onto the group from a `disabled` parent TextField.

## API Reference

### InputGroup Props

InputGroup renders a `<div role="group">`. Inside a [TextField](/docs/components/text-field) it reads Kobalte's form-control context to mirror the field's invalid/disabled state and inherit the `variant`.

| Prop        | Type                       | Default     | Description                                                     |
| ----------- | -------------------------- | ----------- | --------------------------------------------------------------- |
| `variant`   | `"primary" \| "secondary"` | `"primary"` | Visual variant. `primary` has a shadow; `secondary` is lower emphasis, for surfaces. Falls back to the parent TextField's variant. |
| `fullWidth` | `boolean`                  | `false`     | Whether the input group should take full width of its container |
| `class`     | `string`                   | -           | Additional CSS classes                                          |
| `children`  | `JSX.Element`              | -           | Child components (Input, TextArea, Prefix, Suffix)              |

*Plus standard `<div>` attributes (including `role`, `aria-label`, `aria-labelledby`, `aria-describedby`).*

### Input / TextArea

The field element is a standalone [Input](/docs/components/input) or [TextArea](/docs/components/text-area) — the same components you use directly inside a [TextField](/docs/components/text-field). When rendered inside an InputGroup they detect the group via context and swap their standalone `.input`/`.textarea` base for the group's `input` slot (and stamp `data-slot="input-group-input"` / `"input-group-textarea"`). All of their props — `type`, `value`, `placeholder`, `disabled`, `readOnly`, `rows`, `autoResize`, … — work unchanged. See their own pages for the full prop reference.

### InputGroup.Prefix Props

| Prop        | Type          | Default | Description                                           |
| ----------- | ------------- | ------- | ----------------------------------------------------- |
| `children`  | `JSX.Element` | -       | Content to display in the prefix (icons, text, etc.)  |
| `class`     | `string`      | -       | CSS classes for styling                               |

*Plus standard `<div>` attributes.*

### InputGroup.Suffix Props

| Prop        | Type          | Default | Description                                                       |
| ----------- | ------------- | ------- | ---------------------------------------------------------------- |
| `children`  | `JSX.Element` | -       | Content to display in the suffix (icons, buttons, badges, etc.)  |
| `class`     | `string`      | -       | CSS classes for styling                                          |

*Plus standard `<div>` attributes.*

### Composition Components

InputGroup works with these parts:

- **InputGroup** - Root container (`InputGroup` is `InputGroup.Root`)
- **InputGroup.Prefix** - Prefix container
- **InputGroup.Suffix** - Suffix container

The field element is a standalone **[Input](/docs/components/input)** or **[TextArea](/docs/components/text-area)**, placed directly inside `InputGroup` (there is no `InputGroup.Input`/`InputGroup.TextArea`).

## Rendered Elements

Each part renders a fixed element (no polymorphic `as`).

| Component           | Default Element |
| ------------------- | --------------- |
| `InputGroup`        | `<div>`         |
| `InputGroup.Prefix` | `<div>`         |
| `InputGroup.Suffix` | `<div>`         |
| `Input`             | `<input>`       |
| `TextArea`          | `<textarea>`    |

## Differences from HeroUI React

- No `InputGroup.Input` / `InputGroup.TextArea`. Like TextField, InputGroup takes a
  standalone `Input`/`TextArea` as its child, which re-slots itself via context — one
  composition model for the whole library, and a plain `<Input>` dropped into a group
  "just works". Upstream wraps React Aria's Input as `InputGroup.Input`.
- State comes from the parent TextField using Kobalte's prop names — `disabled`,
  `required`, and `validationState="invalid"` (instead of `isDisabled`,
  `isRequired`, and `isInvalid`). InputGroup mirrors the field's invalid/disabled
  state onto the group automatically.
- Hover and focus-within styling use native CSS selectors on the group, so there
  are no `data-hovered`/`data-focus-within` attributes to bridge.
- No render-prop `children`/`className` (React Aria's `Group` render props) — use
  plain children.
- The parts render fixed elements and are not polymorphic (no `as` prop).
- Click-to-focus skips interactive controls. Upstream's group handler focuses the
  field on any click it receives, relying on React Aria's Button to swallow its own
  click (`usePress` → `stopPropagation`). Kobalte's Button doesn't stop propagation,
  so — like shadcn's InputGroup — we gate on the click target: a click inside a
  `button`/`a`/`[role="button"]` keeps its own focus; only "dead space" focuses the
  field.
- Interactive suffix examples use the ported components' Kobalte-style APIs: Button
  uses `onClick`/`disabled` (not `onPress`/`isDisabled`), and the TextArea demo's
  Tooltip uses the compound `Tooltip.Trigger as={Button}` + `Tooltip.Portal`
  structure instead of upstream's flat children.
